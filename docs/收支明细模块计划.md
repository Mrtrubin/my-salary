# 收支明细模块 · 实施计划

## 一、目标
新增管理端「收支明细」模块：记录所有收入/支出，支持手动录入（金额、tag、精确到秒的时间），提供本月/本年度等可视化聚合；并与三类工资条联动——生成工资条时自动生成对应支出，删除工资条时自动删除对应支出。

## 二、现状调研结论（关键）
- 工资条共 **3 张表**：`salary_records`（主播）、`host_salary_records`（主持）、`staff_salary_records`（员工），均含 `net_cents`、`status`、`period_start/end`。
- 生成路径：各自 `settle_*` RPC 内 `insert/update`（`lib/api/data.ts:1067/1303/1415`）；删除当前**仅发生在** `p_replace_overlapping=true` 的重叠替换里（`20260929085656...sql:87/297`，员工侧无删除）。
- 现有触发器均为 BEFORE INSERT/UPDATE，**无 DELETE 触发器**，也未在工资表上做过联动。
- 管理端 Shell 为 `app/(admin)/admin/layout.tsx` 的 `NAV_ITEMS` 数组 + 文件路由；权限靠布局的 `AuthGuard role="admin"` + 数据库 RLS(`is_admin()`)。
- **未安装任何图表库**；金额统一「分」存整数，`lib/format.ts` 已有 `formatCentsToYuan` / `formatDateTime`（精确到秒）。
- 迁移为 `supabase/migrations/<时间戳>_*.sql`，遵循 `security definer` + `revoke/grant` + RLS 惯例（参考 `20261010001000_anchor_reward_records.sql`）。

## 三、数据模型（新增迁移）
> 记账口径（已定）：**不使用单独字段，用 `amount_cents` 正负表示收支**——`amount_cents >= 0` = 收入，`amount_cents < 0` = 支出。
> 工资条是支出 → 存 `-net_cents`；负数工资（net<0）自然变正 → 记为收入。金额约束改为「无符号限制」。

`public.ledger_entries`
- `id uuid pk`
- `amount_cents bigint not null`（**带符号**：正=收入、负=支出、0=收入）
- `tag_id uuid references ledger_tags(id) on delete set null`
- `occurred_at timestamptz not null`（DB 存 UTC，前端显示本地；精确到秒，可编辑）
- `note text`
- `source_type text check in ('manual','anchor_salary','host_salary','staff_salary') default 'manual'`
- `source_id uuid`（工资记录 id；手动为空）
- `created_by uuid references profiles(id) on delete set null`（手动=操作管理员；自动为空）
- `created_by_type text check in ('system','user') not null default 'user'`（自动=system 显示「系统生成」；手动=user 显示上传人姓名）
- `created_at / updated_at`
- 唯一约束 `unique (source_type, source_id)`（自动记录不重复、按来源删除）

`public.ledger_tags`（字典表）
- `id uuid pk`、`code text unique`（**稳定标识**，系统保留标签禁删禁改名）、`name text`、`status`、时间戳
- 标签**通用**（不区分收支）
- 预置系统标签（带 code）：`salary`（工资）、`other_income`（其他收入）、`other_expense`（其他支出）等；触发器按 `code` 定位，缺失则整单结算报错回滚

> 备选：tag 若不想建表，可直接在 `ledger_entries` 存 `tag text`。建议建字典表，便于分组聚合与统一维护（见决策点）。

## 四、工资条联动机制（核心）
在 3 张工资表上各挂触发器，共用一个 `security definer` 函数 `sync_salary_ledger()`，通过 `TG_TABLE_NAME` / `TG_OP` 分支：
- `AFTER INSERT`：写入 `amount_cents = -new.net_cents`（支出为负、负数工资自动为正=收入）、`occurred_at = period_end 当天 23:59:59 UTC`、`source_type/source_id` 对应、`tag` 按工资类型（主播/主持/员工工资，按稳定 code 定位）、`created_by_type='system'`、`created_by=null`（展示「系统生成」）。`net_cents=0` 照常写入（金额 0）。
- `AFTER DELETE`：`delete from ledger_entries where source_type=? and source_id=old.id`。
- `AFTER UPDATE OF net_cents`：同步金额（覆盖重算/改额；`occurred_at` 不覆盖，保留管理员已改的时间）。
- 找不到对应系统标签 → 抛错，**整单结算回滚**。
- 自动记录在 UI 上仅 `occurred_at` 可改，其余只读；允许删除（删后不会立即重建，待工资条下次变更才重建）。

优点：无需改动任何现有 `settle_*`/`recompute_*` RPC，天然覆盖所有创建/删除路径（含重叠替换删除）。

### 新增：删除「未完成工资条」功能（本次需求）
- 三类工资条（主播/主持/员工）都支持删除，条件 `status <> 'completed'`（**含 `confirmed`**）。
- 仅管理员；删除前二次确认；不额外写状态日志（原有状态日志随 FK 级联删除）。
- 实现为各自的 `security definer` RPC `delete_*_salary_record(p_id)`，配合 DELETE RLS；删除时触发器自动清掉对应 ledger 记录。
